# AGENTS.md

A DeepSeek Harness plugin project, laid out the same way deepseek-harness lays
out its own packages. Generated by `@rdmu/create-dsh-plugin`.

**Read [docs/plugin-authoring.md](docs/plugin-authoring.md) before changing
anything under `packages/`.** It covers the common path in full — the two plugin
shapes, `inject`, config, effects, the tool contract, testing — and the plugin
under `packages/plugin/` is a working instance of all of it.

**Whatever the docs do not state, read it from dsh itself rather than inferring
it.** They describe one plugin's worth of dsh, not dsh's surface area: most
services, most events, and most fields of the option objects they show are
deliberately absent. Two local routes, both already set up in this project:

```sh
# implementation — the pinned release's full source, indexed as its own code graph
codegraph explore 'how tool timeouts are enforced' --path .dsh-source/dsh-v<version>
pnpm run dsh:graph                      # fetch + index; postinstall already ran this

# contract — every published tarball keeps its JSDoc, and grep is faster
pnpm run trace @deepseek-ai/dsh-tools   # paths to its .d.ts, README, snapshot, upstream
```

From an agent, prefer the codegraph MCP tools with `projectPath` set to the
snapshot directory; the `dsh-source` skill under `.claude/skills/` carries that
workflow, and `.mcp.json` already wires the server.

Reach for one of these whenever you would otherwise guess. The compiler catches a
misspelled name; it does not catch a waterfall listener that never calls `next()`,
a `render` that is not pure, or a config key that does not exist — and dsh's own
source and JSDoc state all three. [docs/tracing-dsh.md](docs/tracing-dsh.md) is
the full reference.

## Layout

```
packages/
  plugin/hello/          the plugin: one tool, one prompt section
  bundle/hello-bundle/   the patch layer that mounts it into a dsh profile
docs/                    authoring guides — the common path, plus how to trace the rest
scripts/                 tooling shipped by the scaffold; not linted or built here
.dsh-source/             the pinned dsh release's source, fetched and indexed; never committed
tsconfig.base.json       shared compiler options; also the vitest paths facade
tsconfig.json            the aggregate solution `tsc -b` builds
```

`scripts/` is excluded from lint and from the TypeScript solution: those files
arrive already typechecked and linted from `@rdmu/create-dsh-plugin`, and re-checking
them here would only ask you to maintain someone else's code. Your own code lives
under `packages/`.

## Commands

```sh
pnpm install
pnpm run check          # typecheck + lint + test + build — run this before pushing
pnpm run test           # vitest
pnpm run test:coverage  # per-file thresholds
pnpm run typecheck      # tsc -b
pnpm run lint           # oxlint, type-aware
pnpm run build          # tsc -b, then tsdown bundles lib/types → lib
pnpm run pack:bundle    # build + pack the bundle tarball for `dsh plugin add`
pnpm run trace <pkg>    # where an installed dsh package's contract can be read
pnpm run dsh:graph      # fetch the pinned dsh source and index it (--dry-run, --force)
```

## Conventions that are not negotiable

These are dsh's, not this project's. Breaking one produces a plugin that fails in
ways local tests do not catch.

- **One export shape per module.** A function plugin named-exports `name` /
  `inject` / `Config` / `apply` and has **no default export**. A service plugin
  default-exports its `Service` class. Mixing them makes the dsh Loader discard
  the namespace, so `inject` is never read.
- **`@deepseek-ai/cordis` and every dsh package are peerDependencies** (plus
  devDependencies for tests). Bundling a copy creates a second module singleton
  and your registration lands in a registry nobody reads.
- **Every contribution goes through an effect** — `ctx.tools.register()`,
  `ctx.systemPrompt.section()`, `ctx.on()`, or `ctx.effect()`. Never clean up by
  hand in `apply`.
- **Waterfall listeners must call `next()`** to delegate. Returning without it
  short-circuits every other listener.
- **Deployment-varying values are `Config` fields**, settable from `cordis.yml`.
  A `DEFAULT_*` constant is not configurability.
- **Misconfiguration fails loud at load.** Validate in `apply` and throw.
- **Model-facing text carries task vocabulary only** — no UI, transport, or class
  names in a tool description, rendered result, or error message.
- **`exec.signal` reaches every blocking await** in a tool body.
- **Timeout is deployment policy**, declared as `timeoutMs`, never a model
  argument.
- **Tests mount real services.** A hand-built fake `ctx.tools` proves only that
  the mock was called. Every plugin test suite must also dispose the fiber and
  assert the contribution is withdrawn — that is what makes hot reload safe.
- **Types-only files stay types-only.** `src/types.ts` holds no runtime code.
- **Tests live at `packages/<group>/<pkg>/tests/`**, never `src/__tests__/`.

## Style

Enforced by `pnpm run lint`, matching dsh: no semicolons, single quotes, 2-space
indent, trailing commas on multiline, 140-column limit. Every module and exported
symbol carries JSDoc stating its non-obvious contract; function-like exports
document `@param` and non-void `@returns`.

Comments state contracts and consequences, not narration. Do not restate what the
code says, do not describe what you changed, do not preserve review history.

Coverage is per-file 100%, and the generated example starts there. When a line
genuinely cannot be exercised, add `/* v8 ignore next -- <why> */` naming the
reason; do not lower the threshold.

## dsh versions

Every `@deepseek-ai/dsh-*` dependency is pinned to one exact version — the
version of the `@rdmu/create-dsh-plugin` release that generated this project. dsh
packages are cut as one set and are not independently compatible, so **never bump
one alone**. Upgrade them all together, then run `pnpm run check`.

## Adding a package

1. `mkdir -p packages/<group>/<name>/{src,tests}`
2. Copy `package.json` and `tsconfig.json` from `packages/plugin/hello` and adjust.
3. Add one `references` entry to the root `tsconfig.json`.
4. Add one `paths` entry to `tsconfig.base.json` pointing at `src`.
5. If it should mount in a profile, add a row to the bundle's `cordis.patch.yml`.
